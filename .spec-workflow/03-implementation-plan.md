# 03. 実装計画

## フェーズ1: 環境構築（Docker + Ollama + Streamlit）

### タスク

1. `Dockerfile` 作成（Python 3.10 + Streamlit）
2. `docker-compose.yml` 作成（Ollama + ollama-init + アプリ）
   - `ollama-init` サービスで `ollama pull ${OLLAMA_MODEL}` を自動実行するよう設定
3. `requirements.txt` 作成
4. `.env.example` 作成
5. `.gitignore` 作成（credentials/、.env、__pycache__等）
6. `docker compose up` で全サービスが起動し、モデルのダウンロードが自動開始されることを確認
7. `docker compose logs ollama-init` でpullの進捗・完了を確認できることを確認

### 完了条件

- `docker compose up -d` でStreamlit（8501）とOllama（11434）の両方にアクセスできる
- `ollama-init` によりモデルが自動でダウンロードされ、手動の `ollama pull` が不要である

## フェーズ2: Streamlit UI基本画面

### タスク

1. `app/main.py` — 基本レイアウト作成
   - タイトル・説明テキスト
   - 画像アップロードウィジェット（`st.file_uploader`、カメラ入力対応）
   - フォーマット入力テキストエリア（`st.text_area`）
   - 「実行」ボタン（`st.button`）
   - 結果表示エリア
2. `app/config.py` — 環境変数読み込み

### 完了条件

- スマホブラウザからアクセスして画像アップロード・テキスト入力ができる

## フェーズ3: プロンプト解析モジュール

### タスク

1. `app/parser.py` — フォーマット文字列のパーサー実装
   - `A列: 商品名, B列: 価格, ...` 形式を解析
   - `{"A": "商品名", "B": "価格", ...}` のマッピングを生成
   - 「処理日」を含む項目の検出とシステム日付による自動補完ロジック

### 完了条件

- 各種フォーマット文字列を正しく解析できる（ユニットテスト）

## フェーズ4: Ollama API連携（Vision LLM）

### タスク

1. `app/llm.py` — Ollama REST API呼び出し
   - 画像のbase64エンコード（送信前に長辺1280pxにリサイズ）
   - `/api/chat` エンドポイントへのリクエスト組み立て
   - システムプロンプト + ユーザープロンプトの構築
   - HTTPタイムアウト120秒を設定
   - JSON出力の抽出・パース
   - 不正JSON時のリトライ（最大2回）
2. 画像サンプル（野菜ラベル等）でのテスト

### 完了条件

- サンプル画像から正しいJSON形式でデータが抽出される

## フェーズ5: Googleスプレッドシート連携

### タスク

1. `app/sheets.py` — gspread連携
   - サービスアカウント認証
   - スプレッドシートオープン
   - `append_row` でデータ追記
   - エラーハンドリング（認証エラー、権限エラー等）

### 完了条件

- 抽出データがスプレッドシートの最終行に正しく追記される

## フェーズ6: 結合・E2Eテスト

### タスク

1. `app/main.py` で全モジュールを結合
2. 画像アップロード → LLM抽出 → プレビュー表示 → スプレッドシート追記の一連のフロー確認
3. エラーケースの確認（Ollama未起動時、不正画像、スプレッドシート接続エラー等）
4. スマホブラウザでの操作確認

### 完了条件

- 野菜ラベル画像で端末からスプレッドシートまでのフルフローが動作する
