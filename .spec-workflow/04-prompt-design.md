# 04. LLMプロンプト設計

## 1. プロンプト構造

ローカルVision LLMに送るプロンプトは、**システムプロンプト**と**ユーザープロンプト**の2層構造で構成する。

## 2. システムプロンプト（固定部分）

```
あなたは優秀なデータ入力アシスタントです。
添付された画像から、ユーザーが要求する項目を正確に読み取り抽出してください。

【絶対ルール】
1. 出力は必ずJSON配列のみとすること
2. 書類に同種の明細・品目が複数ある場合は、各項目を配列の1要素として出力すること
3. 項目が1つのみの場合も必ず配列で返すこと（例: [{"商品名": "キャベツ"}]）
4. マークダウン記法（```json 等）は使用しないこと
5. 説明文、前置き、後書きは一切含めないこと
6. 画像から読み取れない項目は値を null とすること
7. 数値は文字列として出力すること（例: "380"）
8. 日本語テキストはそのまま日本語で出力すること
```

## 3. ユーザープロンプト（動的部分）

ユーザーが入力したフォーマットから自動生成する。

### 入力例

```
A列: 商品名, B列: 価格, C列: 生産者, D列: 出荷日, E列: JANコード
```

### 生成されるユーザープロンプト

```
以下の項目を画像から抽出して、JSON配列形式で返してください。

【抽出項目】
- 商品名
- 価格
- 生産者
- 出荷日
- JANコード

【出力例（明細が1件の場合）】
[{"商品名": "値", "価格": "値", "生産者": "値", "出荷日": "値", "JANコード": "値"}]

【出力例（明細が複数件の場合）】
[{"商品名": "値", ...}, {"商品名": "値", ...}]
```

### フリーフォームモード（フォーマット未指定時）

フォーマットが指定されていない場合、LLMが画像から読み取れる主要な情報を自由に返す。

```
この画像に記載されている主要な情報をすべて抽出して、JSON配列形式で返してください。
明細が複数行ある場合は各行を配列の1要素として出力してください。
キー名は日本語で、画像から読み取れる実際の項目名を使用してください。

【出力例（レシートの場合）】
[{"品名": "キャベツ", "数量": "1", "金額": "198"}, {"品名": "豆腐", "数量": "2", "金額": "158"}]
```

## 4. 出力例（期待されるLLMレスポンス）

サンプル画像（野菜ラベル）に対する期待出力:

```json
[
  {
    "商品名": "キャベツ",
    "価格": "380",
    "生産者": "山下 太郎",
    "出荷日": "2018年1月1日",
    "JANコード": "2101001003801"
  }
]
```

## 5. JSONパース戦略

LLMの出力にはマークダウンコードブロック等が混入する場合がある。以下の順序でパースを試みる:

1. そのまま `json.loads()` を試行
2. 失敗した場合、正規表現 `\[.*\]` で配列ブロックを抽出して再試行（`re.DOTALL`フラグ使用）
3. 配列が見つからない場合、`\{.*\}` でオブジェクトブロックを抽出してリストに変換
4. それでも失敗した場合、リトライ（最大2回、プロンプトにJSON制約を強調して再送信）
5. 最終的に失敗した場合はユーザーにエラーを表示

## 6. システム補完項目

以下のキーワードが項目名に含まれる場合、LLMには送信せずプログラム側で値を補完する:

| キーワード | 補完値 |
|-----------|--------|
| 処理日 | 当日の日付（`YYYY/MM/DD` 形式） |
| 登録日時 | 現在日時（`YYYY/MM/DD HH:MM` 形式） |

これらの項目はLLMへの抽出要求からは除外し、レスポンスに後からマージする。
