# 01. 要件定義

## 1. プロダクト概要

**SnapSpread** は、スマートフォン等で撮影した帳票（レシート、ラベル、請求書など）の画像をアップロードし、ユーザーが指定したフォーマットに従ってローカルVision LLMで情報を読み取り、Googleスプレッドシートの指定列に自動追記するWebアプリケーション。

### 想定ユーザー

- スマートフォンから帳票を撮影して登録する現場作業者
- PCブラウザからまとめて帳票を処理する管理者

### 想定帳票

- 農産物ラベル（商品名、価格、生産者、出荷日、JANコード等）
- レシート
- 請求書
- その他、定型的な帳票全般

## 2. 機能要件

### F-01: 画像アップロード

- スマホ・PCから画像ファイル（JPEG, PNG）をアップロードできる
- スマホのカメラから直接撮影してアップロードできる
- 複数枚の同時アップロードは初期バージョンでは1枚ずつとする
- アップロード後、LLMへ送信する前に**長辺1280px以内**にリサイズする（アスペクト比は維持）
  - 理由: Vision LLMの推論速度と精度のバランスが最も良いサイズ
  - リサイズ後はJPEG品質85でエンコードしてメモリ上で処理する（ディスク保存しない）

### F-02: 抽出フォーマット指定

- ユーザーがテキストボックスで「どの列に何のデータを抽出するか」を自由に指定できる
- 入力例: `A列: 商品名, B列: 価格, C列: 生産者, D列: 出荷日, E列: JANコード, F列: 処理日`
- フォーマットはStreamlitの `st.session_state` を使いタブセッション中保持される
  - **保持範囲**: 同一ブラウザタブ内のセッション（タブを閉じる・リロードするとリセット）
  - **複数タブ**: タブごとに独立したセッションとなり、タブ間でフォーマットは共有されない
  - **設計方針**: シンプルさを優先しサーバーサイドでのフォーマット永続化は行わない。毎回入力が手間な場合は将来のプリセット機能で対応する
- よく使うフォーマットをプリセットとして保存・選択できる（将来拡張）

### F-03: データ抽出・解析

- アップロード画像とユーザー指定のフォーマットをローカルVision LLMに送信
- LLMはJSON形式で抽出結果を返す
- 「処理日」など画像に存在しない項目はシステム側（当日の日付等）で自動補完する
- LLMの応答が不正なJSON場合はリトライまたはエラーを表示する

### F-04: スプレッドシート追記

- 抽出データをGoogleスプレッドシートの最終行に追記（`append_row`）
- 対象スプレッドシートは環境変数で指定
- 列の順序はユーザーが指定したフォーマット（A列、B列…）に従う

### F-05: 結果表示

- スプレッドシートへの追記成功/失敗を画面に表示
- 抽出されたデータをテーブル形式でプレビュー表示
- エラー時は原因をわかりやすく表示

## 3. 非機能要件

### 性能

- LLM推論はローカル実行のため、ハードウェア依存（10〜30秒程度を想定）
- 処理中はプログレス表示を出す
- Ollama APIへのHTTPリクエストタイムアウトは **120秒** とする
  - 理由: CPUのみの環境でqwen2.5-vlを動かした場合に1分超かかるケースを考慮
  - タイムアウト到達時はユーザーに「処理がタイムアウトしました。再試行するか、より軽量なモデルへの切り替えを検討してください」と表示する

### セキュリティ

- サービスアカウントのJSONキーはGitリポジトリに含めない（`.gitignore`対象）
- アップロード画像はサーバー上に永続保存しない（処理完了後に削除）

### 可用性

- ローカル実行前提のため、Ollamaが起動していない場合は明確なエラーメッセージを表示

### 環境前提

- Google Cloud Consoleでの以下の設定は手動で完了している前提
  - Google Sheets API と Google Drive API の有効化
  - サービスアカウント作成・JSONキーダウンロード済み
  - 対象スプレッドシートにサービスアカウントのメールをEditor権限で共有済み
- Ollamaがインストール済み、またはDocker Composeで起動可能な状態
